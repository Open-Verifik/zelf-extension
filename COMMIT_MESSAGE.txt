fix: preserve transaction amount when API returns invalid values

Fixed critical issue where transaction amounts were displayed as 0 instead
of the actual sent amount when blockchain APIs returned incomplete data.
This primarily affected Solana transactions but could occur with any
token/network.

Problem:
- API sometimes returns tokensTransferred: [] and amount: "" for
  transactions that haven't fully propagated
- Empty strings were converted to 0/NaN, overwriting the original amount
- Users saw incorrect transaction amounts immediately after sending

Solution:
- Implemented defensive merge strategy in WalletService.mergeTransactionData()
- Preserves original amount, fee, fiatFee, and total when API values are
  invalid (0, NaN, undefined, null, or empty)
- Only updates values if API provides valid data matching original
- Added _originalPendingTransaction property to TransactionReceiptComponent
  to preserve original data across API retries
- Consolidated duplicate merge logic into shared utility method

Technical Changes:
- wallet.service.ts:
  * Added public mergeTransactionData() method for shared merge logic
  * Updated addTransactionToPending() to intelligently merge updates
  * Preserved _mergePendingTransaction() as deprecated alias

- transaction-receipt.component.ts:
  * Added _originalPendingTransaction property to store original pending tx
  * Updated _requestTransactionDetails() to preserve original across retries
  * Simplified _mergeTransactionData() to delegate to WalletService

Impact:
- Users now see correct transaction amounts immediately
- Works for all tokens/networks, not just Solana
- Status and other fields still update correctly from API
- Improved code maintainability through consolidation
